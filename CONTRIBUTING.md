# Contribute a small, reproducible improvement

Keep HQ in control of consultations and maintenance follow-up.
Use the existing native AGY and scheduling interfaces.
Prefer a targeted fix or clearer template over new infrastructure.
Use synthetic fixtures for every report or failure example.
Do not submit account data, private prompts, transcripts, customer information, or native logs.

For a compatibility report, state the operating system, Python version, and CLI versions.
State the exact command and observed behavior.
Separate account-specific availability from a product capability.
Do not include credentials or full configuration files.

For adapter changes, add a relevant offline test.
Run the tests, demo, and package checker from the README.
Update `PUBLIC_FILES.txt` when you intentionally add a public file.
Review the file contents before changing the allowlist.
Do not add dependencies or services to solve a documentation problem.

Never post a real secret in a public issue.
Use the hosting platform's private reporting mechanism when one is available.
